# Testing notes

Moved from CLAUDE.md on 2026-09-28 (#282). Edit here, not in CLAUDE.md, which keeps a one-line map entry for this file.

- **`spec/sortplanner_spec.lua`'s `applyPlan` is a hand-written executor simulator behind about 55 assertion sites, so whatever it does not model is untested by construction.** It takes exactly `op.count` from the source, which is faithful rather than lazy: since #169 `liftFromBank` decides the split from what the slot holds now, and both of its branches move exactly `op.count`. Being label-blind is what lets it CHECK the label instead of simulating from it, and it does: `op.op == "split"` exactly when `src.count > op.count`, which is `opLabel`'s rule verbatim (#161). That is one assertion covering every call site in both directions, and it is why an `op.op`-aware source take would have been the wrong fix after #169: it would have modelled the executor v0.39.5 retired. An optional fourth argument `maxStackByItem` holds a same-item merge to the same ceiling `applyOpToState` enforces in production. The one divergence left is a refused op: `applyPlanPartial` trims to a prefix, while a real partial pass leaves holes, because the executor advances `opIndex` on a refusal too.
- **The AceGUI mock's TabGroup follows the library step for step, and the guard on `SelectTab`'s fire is the load-bearing part (#121).** Real `SelectTab` (`AceGUI-3.0/widgets/AceGUIContainer-TabGroup.lua`) marks the matching tab frame and clears the rest, records the value on `self.status or self.localstatus` whether or not anything matched, and fires `OnGroupSelected` **only when the value is one the group currently holds**. Unguarded, a spec would build a tab the group does not hold. It does not call `ReleaseChildren`: production's `GBL:SelectTab` does that itself, so a release in the mock would release twice. The mock was `self._selectedTab = tab` and nothing else until #121, so five production paths had never run under test (`RebuildTabs` selecting the default tab, `RefreshUI`'s unbuilt branch, the Consumption player link, `OpenRestockTab`, and the Layout tab's inner group building its own content). `_selectedTab` is kept and stays unconditional like `status.selected`, so it names the value handed in rather than the tab that was built: anything proving a tab opened reads `GBL.activeTab`. Four shapes to know when writing against it. **The frame work lives in `BuildTabs`, not `SetTabs`**, because production replaces `BuildTabs` (`UI/UI.lua` wraps it to right-align the utility tabs) and calls the original from the wrapper; with the frames built in `SetTabs` a wrapper that dropped the original still left a populated list and no spec could tell, while in the client the list is built there and nowhere else. **A TabGroup whose `SetTabs` was never called holds an empty tab list**, so nothing fires and a hand-built container is unaffected, which is what keeps the fan-out off most of the suite; `localstatus` is the field that is load-bearing there (nothing calls `SetStatusTable` on a tab group, so it is the only table `status.selected` can land in), while `tabs = {}` is insurance a mutation pass showed nothing needs yet. **`BuildTabs` hides the frames past a shrunken list without clearing their `value`, and `SelectTab` walks hidden frames too**, so a bar that shrank can still match a stale value; the mock replicates that rather than correcting it, since a mock stricter than the library hides it. `RebuildTabs` validates `activeTab` against the new list before selecting, so it is off that path, and since #244 so is `OpenRestockTab`, which used to pass a bare literal and now asks `GBL:HasAccessTab` first (see the `UI/UI.lua` bullet in `.claude/rules/ui.md`). **Two production sites still hand the group a value nothing validated, and both are safe by coincidence rather than by a check**: the Consumption player link passes a bare `"transactions"` (`UI/UI.lua:1348`), which is safe only because Transactions and Consumption come from the same branch of `AccessTabs`, so a rank that can be looking at the link can always reach the target, and because `ReleaseChildren` drops the link's callback when the bar shrinks; and `RefreshUI`'s fallback passes `self.activeTab or "transactions"` (`UI/UI.lua:330`), whose `or` branch is validated by nothing and whose stale-`activeTab` case is filed. A spec that wants the surplus-frame behaviour drives the widget's `SelectTab` directly, since no production caller reaches it deliberately. And **the tab-group fields and methods are gated on the widget type**, because this constructor is shared by every widget: a Frame with a `SelectTab` is not a harmless extra, since `UI/UI.lua` points the main frame's status table at `db.profile.ui` and the write would land in SavedVariables.
- **The AceDB mock models both halves of the library, and both are transcriptions rather than paraphrases (#77).** `applyDefaults` is `copyDefaults` and `removeDefaults` is itself, copied branch for branch from `Libs/AceDB-3.0/AceDB-3.0.lua` (`:88-131` and `:134-176`), including three branches this addon's defaults cannot reach: the `**` wildcard, the scalar `*`, and the blocker argument only `**` passes. Porting the reachable half is exactly how the mock came to model a login and never a logout, so the unreachable branches are deliberate and carry synthetic cases. **`db:_simulateLogout()` strips in place**, so `db.global` becomes the on-disk image, and `db:_simulateLogin()` is the next login over that file; run the pair to model an upgrade, because what AceDB does to a guild ALREADY in the file is a different path from what it does to a fresh one, and the mock had no second path at all before #77. **Absence is read with `rawget`**, never by indexing: a wildcard metatable turns a read into a write, which is also why `removeDefaults` clears the metatable on its first line. Three read-path gaps came out of the same work and one is worth carrying: the vivification used to deep-copy the template, which copies the literal `"*"` key into the new table, so every `guildData.playerStats` in this suite held a phantom player. Seven production sites in `src/Core.lua` walk that table with `pairs`: two each in `MigrateSchemaV2ToV3` and `RepairPlayerNames`, and one each in `MigrateDeduplicateRecords`, `MigrateCrossSlotDedup` and `CleanupWithEventCounts`. **Four sit inside migrations, and two resolve every name they find and write it back**: the merge loops in `MigrateSchemaV2ToV3` and `RepairPlayerNames`, of which only the first is a migration (the second runs from the first `GUILD_ROSTER_UPDATE`). The other five are clear-and-repopulate loops that resolve nothing, and the one in `CleanupWithEventCounts` is runtime sync cleanup rather than a migration. One migration storing a resolved phantom is the whole of it, and it is enough. **Nothing went red when it was removed**, which is the lesson rather than a relief: no case had ever asserted what that table contains, only what its own fixture put in it, so an extra key was invisible in both directions. `spec/savedvariables_spec.lua` holds the round trip, and its last describe runs the same defaults through a real AceDB from `spec/vendor/` and compares the file each side leaves behind, because a hand port can only ever agree with itself.

### Wire-contract fixtures

`spec/wire_contract_spec.lua` is the one spec that does not use the serializer mock. **`spec/vendor_helpers.lua` is where a real Ace3 library gets loaded**, by `dofile` (`require` cannot be used: the module names contain a dot, which `require` turns into a path separator), stashing and restoring `_G.LibStub` and `strmatch` around the load. Real LibStub reads the existing global and evaluates `LibStub.minor < 2`, which the suite's mock does not have, so skipping the stash either throws or leaves the mock registry replaced for whatever runs next in the same file. `spec/wire_helpers.lua` is the serializer-shaped API over it and holds no loading of its own since #77, when `spec/savedvariables_spec.lua` needed a real AceDB the same way. The addon's own mixed-in `Serialize`/`Deserialize` are never touched, and neither is its AceDB instance. **`loadVendored`'s third argument generalises the `strmatch` shim**: a global a vendored library reads AT LOAD and production never reads is installed for the load and restored after, rather than becoming a permanent entry in `mock_wow.lua`, which exists to describe the client the addon actually talks to. AceDB needs seven of them, six profile-key globals it computes once at load and `CreateFrame`, because it owns one frame solely to catch `PLAYER_LOGOUT` and the mock's frames have no `RegisterEvent`.

**The libraries come from `spec/vendor/`, not `Libs/`.** `Libs/` is gitignored and fetched by the packager from `.pkgmeta` externals, so it exists only on a machine that has run the packager: CI checks out a tree with none. Committing LibStub (51 lines, public domain), AceSerializer (287 lines) and, from #77, AceDB (797 lines) under `spec/vendor/` is what makes the suite hermetic. `spec/vendor/README.md` carries the provenance. The generator additionally diffs those copies against `Libs/` when `Libs/` is present, so a developer still finds out when upstream moves while the test run stays deterministic everywhere; that check was verified to fire rather than assumed to, and AceDB is the one of the three where it earns its keep, since its vendored revision is dated 2026-09-18 while the other two have not moved since 2022 and 2014.

**No compression in the harness.** LibDeflate is a pure byte-exact codec this addon neither configures nor extends, so pinning it would test LibDeflate rather than GBL, at the cost of vendoring 3,600 more lines. The test is whether this addon configures the library, not how large it is: AceDB is vendored at 797 lines because GBL hands it a defaults block and every claim in `docs/DATA-MODEL.md` section 2 is about what AceDB does with that block, so pinning it pins our defaults. LibDeflate is handed nothing. `estimateRecordBytes` is documented against AceSerializer output, and the compressed size that matters at runtime is measured live as `syncState.lastChunkBytes`.

**The golden strings in `spec/fixtures/wire/*.lua` are frozen and are not regenerated.** They are what a v0.36.x peer puts on the wire, and "an older peer's bytes still decode" is the contract the `MIN_SYNC_VERSION` floor (#74) rests on. A record-shape change (#67) adds cases beside them; it never rewrites them. `spec/fixtures/generate_wire_fixtures.lua` is an authoring aid for new cases plus a check that every committed string still decodes to its hand-written table; it is not a refresh tool.

Expectations are hand-written from `docs/DATA-MODEL.md`, never pasted from program output, because a characterization fixture built from what the code prints can only ever agree with the code. The `serialized` field records AceSerializer output rather than the compressed and encoded channel bytes, so a reviewer can read the diff. Field order inside those strings comes from `pairs()` and is not meaningful: the tests only ever decode them.

`src/Sync.lua` exposes `_StripForSync`, `_ReconstructSyncRecord` and `_EstimateRecordBytes` for this spec alone. They have no production callers and exist because the codec is otherwise file-local and unreachable.

Two format facts worth not rediscovering: AceSerializer escapes space (and control codes, `^`, `~`) to two bytes, and an **unescaped** space is silently dropped on decode, so a hand-typed payload containing `"Test Guild"` comes back `"TestGuild"`. Pipes and colons, which record ids are built from, pass through unescaped, which is why `estimateRecordBytes` holds as an upper bound for records.
